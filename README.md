# ส่งออก SSOP

เว็บแอปสำหรับดึงรายการผู้ป่วยนอกสิทธิประกันสังคมจาก HOSxP ตรวจข้อมูลและ PDx เลือกคนที่จะส่ง แล้วสร้างไฟล์ ZIP ไปอัปโหลดเอง
โปรแกรมอ่าน HOSxP อย่างเดียว ข้อมูลของโปรแกรมเองเก็บใน SQLite ที่ `data/`

## ติดตั้งและเปิดใช้

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

```bash
cp .env.example .env
```

แก้ค่าใน `.env` โดยใช้ฐานสำเนาและ user ที่มีสิทธิ์ SELECT เท่านั้น จากนั้นเปิดโปรแกรม:

```bash
.venv/bin/python run.py
```

แล้วเข้าที่ https://localhost:5180 โปรแกรมเปิดให้ใช้เฉพาะเครื่องนี้ ถ้าจะใช้ร่วมหลายเครื่องต้องเพิ่ม login และ HTTPS ก่อน

## ติดตั้งบน server ให้เครื่องอื่นเข้าได้

ตัวอย่าง server 192.168.80.88 ใส่ใน `.env` ของ server:

```
HOST=0.0.0.0
ALLOWED_HOSTS=192.168.80.88
PORT=5180
HEALTHID_REDIRECT_URI=https://192.168.80.88:5180/auth/healthid/callback
```

แล้วสร้าง certificate ตาม IP ของ server และเปิดโปรแกรม:

```bash
.venv/bin/python make_cert.py
```

```bash
.venv/bin/python run.py
```

ถ้าเปิด HOST ให้เครื่องอื่นเข้า โปรแกรมจะไม่ยอมเปิดแบบ HTTP ต้องเปิด port 5180 ใน firewall ของ server และต้องลงทะเบียน redirect URL ใหม่กับ MOPH ID ถ้าระบบไม่รับ

## เข้าสู่ระบบ

ทุกหน้าต้องเข้าสู่ระบบก่อน มี 2 วิธี:

1. **บัญชี HOSxP:** ใช้ชื่อผู้ใช้และรหัสผ่านเดียวกับ HOSxP โปรแกรมอ่าน `opduser` อย่างเดียว ไม่ให้เข้าถ้าบัญชีถูกปิด (`account_disable='Y'`) หรือรหัสผ่านหมดอายุ จำกัดกลุ่มผู้ใช้ได้ด้วย `LOGIN_GROUPS` ถ้ากรอกรหัสผิด 5 ครั้งจะล็อก 15 นาที
2. **MOPH ID:** ปุ่ม "เข้าสู่ระบบด้วย MOPH ID" ใช้ Health ID ของ moph.id.th แล้วอ่านโปรไฟล์จาก Provider ID ให้เข้าได้เฉพาะผู้ที่สังกัด `HCODE` หรือรหัสใน `MOPH_ALLOWED_HCODES` ต้องขอ client ID และ secret key ของ Health ID และ Provider ID แล้วใส่ใน `.env` พร้อมลงทะเบียน redirect URL ให้ตรงกับ `MOPH_REDIRECT_URI`

โปรแกรมอ่านชื่อตัวแปรตามเอกสาร key ได้ด้วย ได้แก่ `HEALTHID_CLIENT_ID`, `HEALTHID_CLIENT_SECRET`, `HEALTHID_REDIRECT_URI`, `HEALTHID_BASE_URL`, `PROVIDERID_CLIENT_ID`, `PROVIDERID_CLIENT_SECRET`, `PROVIDERID_API_URL` และ `HOSPITAL_CODE` (รหัสโรงพยาบาลที่อนุญาตให้เข้า)

Cloudflare ของ provider.id.th บล็อกคำขอที่ส่งชื่อโปรแกรมเป็น `Python-urllib` (Error 1010) โปรแกรมจึงส่ง `User-Agent: EMR` แทน เปลี่ยนชื่อได้ด้วย `MOPH_USER_AGENT` ทดสอบ login ด้วย MOPH ID ผ่านแล้วเมื่อ 2026-11-08

redirect URL ที่ลงทะเบียนไว้เป็น `https://localhost:5180/auth/healthid/callback` โปรแกรมจึงเปิดแบบ HTTPS ด้วย certificate ที่สร้างเองใน `data/tls/` ให้เข้าที่ https://localhost:5180 เบราว์เซอร์จะเตือนครั้งแรกว่า certificate ไม่น่าเชื่อถือ ถ้าจะไม่ให้เตือน ให้เพิ่ม `data/tls/localhost.pem` ใน Keychain แล้วตั้งเป็น Always Trust

session อยู่ได้ `SESSION_HOURS` ชั่วโมง (ค่าเริ่มต้น 8) ประวัติการส่งออกบันทึกชื่อผู้สร้าง ZIP และบันทึกการเข้าสู่ระบบไว้ในตาราง `login_log` ของ SQLite

## การตรวจก่อนส่ง

| ระดับ | ความหมาย | ตัวอย่าง |
|---|---|---|
| Error | เลือกส่งไม่ได้ | ไม่มี PDx, PDx เป็นรหัส V-Y, ยอดไม่ตรง, HospMain ผิด |
| เตือน | เลือกส่งได้ | PDx ไม่อยู่ใน `icd10_nhso`, รหัสแพทย์ผิด, สิทธิหมดอายุ |
| เบิกไม่ได้? | ไม่เลือกให้อัตโนมัติ แต่เลือกเองได้ | รหัส Z ไม่อยู่ในรายการที่เบิกได้ |
| เคสพิเศษ | เลือกส่งไม่ได้ ต้องใช้โปรแกรมเดิม | มะเร็ง, Sleep Test, เตรียมเส้นฟอกไต, TeleMed, โควิด |

เซิร์ฟเวอร์ตรวจซ้ำด้วยข้อมูลล่าสุดทุกครั้งก่อนสร้าง ZIP รายการที่เคยส่งแล้วต้องใช้ TFlag E หรือ D และต้องยืนยันก่อน

## ต่างจากโปรแกรมเดิม

- ไม่แก้ข้อมูล HOSxP และไม่สร้างตารางในฐาน ปัญหาต้องไปแก้ใน HOSxP แล้วค้นใหม่
- รายการที่ HOSxP กำหนดไม่ส่ง (`opitemrece_noexport`) เอาติ๊กออกได้ ค่านี้เก็บใน SQLite ของโปรแกรมนี้ ใช้เฉพาะตอนส่งออกจากโปรแกรมนี้ และไม่เปลี่ยนค่าใน HOSxP
- รองรับเฉพาะ HOSxP ไม่รองรับ IMED
- ยังไม่นำเข้าไฟล์ผลตอบกลับ `.BIL`
- นำเข้ารหัส Z ได้เฉพาะไฟล์ `.xlsx`

## ผลเทียบกับโปรแกรมเดิม

เทียบกับ ZIP จากโปรแกรมเดิม 1 ชุด (29 visit, วันที่ไฟล์ 2026-09-30) โดยดึงข้อมูล VN เดียวกันจากฐานสำเนา

- `BillTran` ตรงกันทุกไบต์ ส่วน `BillDisp` และ `OPServices` ตรงกันทุกฟิลด์ ยกเว้นข้อด้านล่าง
- `PrescDT` และ `DispDT` ใน `Dispensing` ต่างกันได้เมื่อ visit มีเวลาสั่งยาหลายเวลา โปรแกรมเดิมหยิบแถวโดยไม่ได้กำหนดลำดับ โปรแกรมนี้ใช้เวลาแรกสุด
- Dx ประเภทเดียวกันเรียงตามรหัส ซึ่งตรงกับชุดนี้ แต่มีตัวอย่างเพียง 1 visit

## สิ่งที่ยังต้องยืนยันก่อนใช้จริง

**กฎสิทธิประกันสังคม:** ฐานนี้เก็บรหัส `SSS` แต่โปรแกรมเดิมเทียบกับ `SS` โปรแกรมนี้จึงให้ PayPlan 80 และตรวจ HospMain กับทุกสิทธิที่ขึ้นต้นด้วย `SS` ผู้ใช้ยืนยันแล้วว่าโปรแกรมเดิมขึ้น Error "HospMain ผิด" เหมือนกันกับ 23 visit ของเดือน ก.ย. 2569 (สิทธิ 29, 35, 36) ส่วนสิทธิ `SSI` ยังไม่มีตัวอย่างที่ HospMain ผิด จึงยังไม่ได้ยืนยัน

ชุดที่เทียบแล้วไม่มีกรณีต่อไปนี้ จึงยังไม่ได้ยืนยัน:

1. **รายการที่ผู้ป่วยจ่ายเอง:** ทุก visit ในชุดนี้ไม่มียอดนี้
2. **แถวหัตถการและรหัส TT:** ไม่มีแถว `OP` ใน `OPServices` และไม่มี Dx แบบ TT
3. **ยาหมวด 4 และ 5, TFlag E/D, `moreicd()`:** ชุดนี้รหัส Dx ตรงตามที่บันทึก แต่ไฟล์นี้ไม่มีโค้ดของฟังก์ชัน จึงยังไม่รู้ว่ากรณีอื่นจะเปลี่ยนรหัสหรือไม่
4. **ทดลองส่งจริง:** ต้องอัปโหลดชุดเล็กเข้าระบบรับไฟล์และดูผลตอบกลับ

## เมนู AIPN (ผู้ป่วยใน)

เปิดที่ https://localhost:5180/aipn หรือกดเมนู "AIPN ผู้ป่วยใน" ค้นตามวันที่จำหน่าย สิทธิ หรือ AN แล้วสร้าง `<HCODE>AIPN<Session>.ZIP` ที่มี XML 1 ไฟล์ต่อ 1 AN ตามรูปแบบใน `aipn.txt`

- Session No เป็นตัวเลข 5 หลัก (10000-99999) โปรแกรมเสนอเลขถัดจากครั้งล่าสุดที่ส่งจากโปรแกรมนี้
- ประเภทการส่ง: ปกติ, ADJ, ADD, AUD
- AuthCode มาจาก `ipt_pttype.claim_code` และ AuthDT ใช้ `auth_datetime` ถ้าไม่มีจะใช้เวลา admit
- สิทธิ SSI (UPayPlan 86) ส่ง Hmain ว่าง ตามไฟล์ของโปรแกรมเดิม
- CareAs เริ่มจากกฎเดิมและเปลี่ยนได้ในตาราง ค่าที่เลือกเก็บใน SQLite
- ติ๊ก "ไม่ส่ง" รายการได้ รวมทั้งเลือกส่งรายการที่ HOSxP กำหนดไม่ส่ง โดยไม่แก้ `opitemrece_noexport`
- การตรวจรายการ (ยาไม่อยู่ใน Drug Catalog, TMT, TMLT, ราคา) ดูเฉพาะรายการที่จะส่ง โปรแกรมเดิมตรวจทุกรายการ
- เคส ODS, ฟอกเลือด (PF), มะเร็ง (SSOCAC) และโควิด ยังต้องส่งด้วยโปรแกรมเดิม

**ผลเทียบกับโปรแกรมเดิม:** ZIP 10117-10119 มี 8 ไฟล์ 7 AN ไฟล์ที่สร้างจากฐานสำเนาตรงทุกไบต์รวม HMAC 6 ไฟล์ ส่วน AN อีก 1 ราย (2 ไฟล์) ต่างเพราะข้อมูลใน HOSxP ถูกแก้หลังส่ง ได้แก่ วันที่หัตถการ (`modify_datetime` 2026-07-23 09:18 หลังส่ง 09:11) และรายการที่กำหนดไม่ส่ง

## เมนู 18 แฟ้ม สปสช. (New e-Claim)

เปิดที่เมนู "18 แฟ้ม สปสช." ค้นตามช่วงวันที่ สิทธิ (มีปุ่มลัด UCS / OFC / SSS / LGO / BKK / พ.ร.บ.) และเลือก OPD / IPD หรือค้นด้วย VN / AN / HN ตรวจตามกฎของ `ส่งออก18แฟ้ม.txt` แล้วสร้าง ZIP ของแฟ้ม TXT 18 แฟ้ม (INS, PAT, OPD, ORF, ODX, OOP, IPD, IRF, IDX, IOP, CHT, CHA, AER, ADP, LVD, DRU, LAB, PHDB) สำหรับอัปโหลดเข้า New e-Claim เอง

- ไฟล์เป็น windows-874 คั่นด้วย `|` มีหัวคอลัมน์ บรรทัดจบด้วย CRLF เหมือนโปรแกรมเดิม
- โปรแกรมเดิมสร้างตาราง temp และแก้ HOSxP (`ovstdiag.diagtype` ของรหัส V-Y) โปรแกรมนี้ใช้ SELECT อย่างเดียว และกำหนด DXTYPE 5 ในไฟล์แทน
- ติ๊ก "ไม่ส่ง" รายการค่าใช้จ่ายได้ เก็บใน SQLite และยังใช้ `opitemrece_noexport` ของ HOSxP เหมือนเดิม
- ยังไม่ส่งผ่าน API และยังไม่สร้าง DBF

**ผลเทียบกับโปรแกรมเดิม:** ชุดตัวอย่าง 56 visit (OPD วันที่ 7 พ.ย. 2569) แฟ้มที่สร้างตรงทุกไบต์ 16 จาก 18 แฟ้ม ที่ต่างคือ OOP (DROPID 24 แถว เมื่อหัตถการเดียวกันบันทึกทั้งใน ovstdiag และห้องฉุกเฉิน โปรแกรมเดิมเลือกแบบไม่แน่นอน) และ PHDB (NAME 2 แถว เมื่อหลายรายการใช้รหัสเดียวกัน) ส่วนผู้ป่วยในยังไม่มีไฟล์ตัวอย่างให้เทียบ

### ส่ง FDH (Financial Data Hub)

ตั้ง `FDH_USER` และ `FDH_PASSWORD` ใน `.env` แล้วด้านล่างหน้า 18 แฟ้มจะมีปุ่ม "ทดสอบเชื่อมต่อ", "PreScreen" และ "ส่ง FDH" ให้เลือกปลายทาง UAT (ทดสอบ) หรือ PROD (ส่งจริง) ใช้รายการที่เลือกและผลตรวจเดียวกับการสร้าง ZIP แปลงเป็นรูปแบบคอลัมน์ของ FDH แบบ UTF-8 ตาม `api_fdh.txt` (ตัด LAB, ADP.BILLMAUD, PHDB.NAME, เพิ่ม ORF.REFERDATE, เปลี่ยน PERMITNO `PG…` เป็น `visit_pttype.auth_code`) แล้วส่งที่ `/api/v2/data_hub/16_files` (PreScreen ส่งที่ `/api/v1/auth/open_api/fda/file` โดยไม่รวม PHDB) สำเนาแฟ้มที่ส่งเก็บใน `exports/FDH_<เวลา>_<zone>_<mode>/` และประวัติการส่งเก็บใน SQLite รายการที่ส่ง PROD สำเร็จจะขึ้นสถานะ "ส่ง FDH แล้ว"

### บัตรทอง OP walk-in หลาย visit ในวันเดียวกัน

ถ้าผู้ป่วยคนเดียวกัน (HN เดียวกัน) ใช้สิทธิ walk-in (`sys_var` Walkin) ที่เป็น UCS มี OP มากกว่า 1 visit ในวันเดียวกัน โปรแกรมจะส่งเบิกครั้งเดียวที่ VN แรก (เวลามาก่อน) โดยรวมเฉพาะในแฟ้มที่ส่งออก ไม่แก้ HOSxP ใช้กับ ZIP, FDH และ New e-Claim
- INS, OPD, AER ใช้แถวของ VN แรก, ORF/OOP/ODX รวมแบบไม่ซ้ำ (dx หลักของ VN หลังเป็น DXTYPE 4), CHT/CHA/ADP/DRU/PHDB รวมยอด, ADP `WALKIN` นับครั้งเดียว
- เลือก visit ใดในกลุ่ม ระบบจะดึง visit อื่นของวันนั้นมาด้วยเอง ในตารางจะขึ้นป้าย "VN แรก (รวม walk-in)" และ "รวมกับ <VN>"
- ถ้าจะให้ dx หลักของ VN หลังเป็น type 2 แทน แก้ `WALKIN_LATER_DXTYPE` ใน `app/nhso18.py`

### ส่ง New e-Claim ผ่าน API

ตั้ง `NHSO_USER` และ `NHSO_PASSWORD` (บัญชี e-Claim ที่สมัครโครงการส่งข้อมูลผ่าน API กับ สปสช. แล้ว ติดต่อ apieclaim@nhso.go.th) ใน `.env` แล้วหน้า 18 แฟ้มจะมีกลุ่ม "New e-Claim" ให้เลือกสิทธิ (ทุกสิทธิ/UCS/OFC/LGO/SSS/NHS) ติ๊กนำเข้าซ้ำ ปุ่ม "ทดสอบ Token" และ "ส่ง New e-Claim" ตาม `api_eclaim_new.txt`: ขอ token ที่ `https://nhsoapi.nhso.go.th/FMU/ecimp/v1/auth` แล้วส่ง JSON ที่มี 16 แฟ้ม (TXT ชุดเดียวกับใน ZIP เป็น base64 MS874, ไม่ส่ง PHDB, LAB เป็น null) ไปที่ `/ecimp/v1/send` ใช้ได้เฉพาะ production เหมือนโปรแกรมเดิม สำเนาแฟ้มเก็บใน `exports/ECLAIM_<เวลา>/` รายการที่ส่งสำเร็จขึ้นสถานะ "ส่ง e-Claim แล้ว"
